# Сборка APK для проверки на телефоне

Терминал Android Studio: **Alt+F12** (PowerShell, Windows).
Все команды выполняются из корня проекта — там, где лежит `pubspec.yaml`.

---

## Шаг 0. Узнать IP компьютера в локальной сети

Телефон и компьютер должны быть **в одном Wi-Fi**.
`localhost` внутри телефона означает сам телефон, поэтому нужен именно IP компьютера.

```powershell
ipconfig
```

Найдите строку **IPv4-адрес** у активного адаптера (Wi-Fi). Выглядит так:

```
IPv4-адрес . . . . . . . . . . . : 192.168.1.50
```

Запомните это число — ниже оно подставляется вместо `192.168.1.50`.

---

## Шаг 1. Подготовить проект

```powershell
flutter clean
flutter pub get
```

`flutter clean` обязателен: были изменены зависимости (добавлена локализация).

---

## Шаг 2. Собрать APK

Одной строкой, подставив **свой** IP из шага 0:

```powershell
flutter build apk --debug --dart-define=API_BASE_URL=http://192.168.1.50:3000/api
```

Сборка идёт 3–10 минут в первый раз.

**Ожидаемый результат** — последняя строка:

```
√ Built build\app\outputs\flutter-apk\app-debug.apk
```

---

## Шаг 3. Найти файл

```
build\app\outputs\flutter-apk\app-debug.apk
```

Полный путь можно вывести командой:

```powershell
(Resolve-Path build\app\outputs\flutter-apk\app-debug.apk).Path
```

---

## Шаг 4. Запустить backend на компьютере

Без него приложение откроется, но вход и планы работать не будут.

Открыть **второй** терминал (в Android Studio — значок `+` рядом с вкладкой Terminal):

```powershell
cd backend
npm run start:dev
```

Дождаться строки:

```
Nexa VPN API ready → http://localhost:3000/api
```

Этот терминал **не закрывать**, пока тестируете.

---

## Шаг 5. Разрешить подключение через брандмауэр Windows

Windows по умолчанию блокирует входящие подключения к порту 3000.
Выполнить **один раз** в PowerShell, запущенном **от имени администратора**:

```powershell
New-NetFirewallRule -DisplayName "Nexa API 3000" -Direction Inbound -LocalPort 3000 -Protocol TCP -Action Allow
```

**Проверка:** на телефоне откройте браузер и введите
`http://192.168.1.50:3000/api/health` (со своим IP).
Должен появиться ответ вида `{"status":"ok"}`.
Если страница не открывается — брандмауэр всё ещё блокирует, либо устройства в разных сетях.

---

## Шаг 6. Установить APK на телефон

**Вариант А — кабелем (проще всего).**
Подключить телефон USB, включить «Отладку по USB» в настройках разработчика, затем:

```powershell
flutter install
```

**Вариант Б — вручную.**
Скопировать `app-debug.apk` на телефон (кабель, Telegram «Избранное», облако), открыть файл на телефоне и подтвердить установку из неизвестного источника.

## Что можно проверить в этой сборке

| Работает | Не работает |
|---|---|
| Онбординг, навигация, все экраны | **Само VPN-подключение** |
| Регистрация и вход | Реальный трафик через туннель |
| Русский/английский язык, переключение | Смена IP-адреса |
| Планы, оформление подписки (mock-оплата) | Оплата настоящими деньгами |
| Ключи доступа, QR-код, копирование | |
| Баннеры, счётчики показов и кликов | |

**Кнопка подключения — это заглушка `MockTunnelManager`.** Она проигрывает анимацию и меняет статус на «Подключено», но трафик никуда не идёт и IP не меняется. Реальный движок — задача #024, и для неё нужна работающая VPS с Xray.

## Проверить локализацию

Настройки → раздел «ПРИЛОЖЕНИЕ» → **Язык**: Системный / English / Русский.
По умолчанию «Системный» — на русском телефоне интерфейс сразу русский.

Обратите внимание, не разъезжается ли вёрстка: русский текст в среднем на 15–20% длиннее английского. Если где-то текст обрезан или наехал на кнопку — пришлите скриншот, поправлю.

Часть экранов (Premium, Профиль, Мой доступ) пока на английском — они переписываются в задачах #022–#023, переведу при переработке.

## Если что-то пошло не так

**`flutter: команда не найдена`**
Flutter не в PATH. Используйте полный путь, например `C:\src\flutter\bin\flutter build apk ...`

**Сборка падает с `Gradle task assembleDebug failed`**
Выполните `flutter clean`, затем повторите. Если не помогло — пришлите последние 30 строк вывода.

**Приложение установилось, но «Нет связи с сервером»**
По порядку: backend запущен (шаг 4)? Правило брандмауэра создано (шаг 5)? Телефон в том же Wi-Fi? IP в команде сборки совпадает с текущим `ipconfig`? IP меняется после перезагрузки роутера — тогда пересоберите с новым.

**Установка блокируется («Play Защита»)**
Это ожидаемо для debug-сборки без подписи. Нажмите «Всё равно установить».
